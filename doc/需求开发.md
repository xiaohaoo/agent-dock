## 1. 项目概述

`agent-dock` 是一个跨平台桌面应用，用于统一管理 Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi 和 MiniMax Code 的 Provider、MCP、Skills、Prompt、会话和用量配置。

项目的核心价值：

1. 用图形化界面替代手工编辑 JSON、TOML、YAML 配置文件。
2. 在多个 AI 工具和多个 API Provider 之间快速切换。
3. 通过本地路由实现协议转换、故障转移和请求观测。
4. 集中管理 MCP、Skills、Prompt 和会话数据。
5. 保留原始配置，提供备份、恢复和安全写入能力。

### 1.2 术语

| 术语 | 含义 |
| --- | --- |
| Provider | 包含连接协议、API 地址、模型及凭据引用的服务配置；工具专属差异由绑定关系管理 |
| 工具 | Agent Dock 管理的 AI 编程客户端或桌面应用 |
| 工具配置投影 | 按工具原生格式，将数据库中的受管配置合并到工具实际读取的文件 |
| 运行模式 | 直连（Direct）、路由（Routing）或聚合（Aggregation） |
| 项目快照 | 按工具组织的资源引用、顺序、配置及版本标识；不等同于资源历史正文备份 |
| 官方 API Provider／官方订阅账号 Provider | 分别使用官方 API 服务和订阅账号认证的连接配置；认证与路由资格分开判定 |
| 工具绑定 | Provider 或资源与工具之间的启用、顺序及工具专属配置关系 |
| 受管字段／受管片段 | Agent Dock 有权修改的明确字段路径或正文范围；未知内容不自动纳入管理 |
| 工具配置快照 | 目标文件的哈希、同步和恢复状态；不等同于项目快照 |
| 路由恢复意图 | 用户期望在重启后恢复的模式；不等同于当前文件模式或实际监听状态 |
| 逻辑请求／上游尝试 | 分别对应 `request_id`／`attempt_id`；一次逻辑请求可包含多次尝试 |
| 首字节耗时／输出速率 | 分别以毫秒和 Token/s 表示；不使用未定义的“响应速度”作为验收指标 |
| API Key／OAuth Token／认证 Header | 分别说明凭据类型，不统一简称为 Key |
| Prompt／指令文件 | 分别指受管正文资源和 `CLAUDE.md`、`AGENTS.md` 等目标文件 |
| Skill／Skills | 单个资源使用 Skill，资源集合或功能模块使用 Skills |
| 工具同步／云同步 | 分别指投影到工具原生文件、跨设备同步配置快照 |
| 待完成操作（pending operation） | 已登记、尚未完成文件发布或数据库提交的操作及恢复依据 |
| 备份／恢复点／临时文件 | 分别指保留副本、特定操作前状态、尚未发布的目标内容 |

## 5. 设置与数据管理

### 5.1 数据目录

项目只使用一种数据目录：程序目录下的 `config` 文件夹。不使用用户主目录，不使用系统应用数据目录，也不提供其他数据目录切换方式。

数据目录固定为：

```text
<程序目录>/config/
```

例如：

```text
D:\Apps\agent-dock\
├── agent-dock.exe
└── config\
    ├── config.db
    ├── backups\
    └── logs\
```

数据目录要求：

1. 首次启动自动创建 `<程序目录>/config`。
2. 启动时检查程序目录和 `config` 目录是否可写。
3. 目录不可写时直接提示用户将程序移动到可写目录后重试，不回退到用户主目录。
4. 应用升级或替换程序文件时，只替换程序文件，不删除 `config` 目录。
5. 安装包和压缩包都必须支持将程序放在普通可写目录中运行。

目录结构如下：

```text
config/
├── config.db                  # 唯一的应用配置和业务数据库
├── backups/                   # 配置和数据库备份
├── logs/                      # 运行日志
├── skills/                    # Skills 文件
└── sessions/                  # 外部会话原始文件缓存
```

### 5.2 数据分类

- Provider、MCP、Prompt、Skills 元数据、项目、路由规则、用量记录、会话索引和应用设置：SQLite。
- Prompt 正文、MCP 非敏感配置、Provider 非敏感配置和项目快照：直接保存在 SQLite，不额外生成应用级配置文件。
- API Key 和 OAuth 凭据：使用系统密钥链保存，SQLite 只保存凭据引用和账号标识。
- 禁止生成或保存 `*_auth.json`、`*_oauth_auth.json` 等认证文件，禁止将登录 Token、刷新 Token 或 API Key 以明文写入 `config` 目录。
- 工具配置文件：将 SQLite 中的受管配置合并到目标工具的原生文件，保留未知字段；外部修改先检测差异，再按同步规则合并或提示重新导入。
- Skills 的仓库信息、版本、启用状态和同步关系：SQLite；Skills 实体文件保留在 `config/skills/`，供工具读取。
- 会话的标题、项目、目录、摘要、Token 和搜索索引：SQLite；原始会话日志保留在工具目录或 `config/sessions/`。
- 备份和日志：保留为文件，避免大体积数据和持续追加内容占用数据库。

### 5.3 数据目录约束

1. SQLite 是应用配置的唯一主存储，结构化配置保存到 `config/config.db`；此约束不限制用户主动触发的脱敏导入、导出文件。
2. 不创建 `~/.agent-dock`、`%LOCALAPPDATA%\agent-dock` 或其他隐藏配置目录。
3. 不提供自定义数据目录、迁移目录或自动回退目录功能。
4. 只有工具必须读取的实体文件、备份、日志和外部会话原始文件落盘；这些文件的索引和元数据必须写入数据库。
5. API Key 和 OAuth 凭据使用系统密钥链；MCP 环境变量、Header 和同步服务配置中的认证信息也按此规则保存。密钥链不可用时提示处理，不回退为数据库或普通文件明文存储。
6. 不生成 `copilot_auth.json`、`codex_oauth_auth.json`、`xai_oauth_auth.json` 或其他同类认证文件。

### 5.4 数据安全要求

1. API Key 不得写入普通运行日志。
2. 配置导出不包含 API Key、OAuth Token、认证 Header 等凭据正文，只保留非敏感配置和凭据引用；导入到其他设备后需重新关联本机凭据。
3. 修改配置前验证目标文件可读写。
4. 文件发布前失败时目标文件保持不变；多文件部分发布或发布后的数据库提交失败时，保留待完成记录、备份及目标状态，显示已发布范围和恢复指引。不得将部分发布报告为完整成功，处理流程见技术实现方案第 9 章。
5. 删除 Provider 前检查是否仍被当前工具或项目使用。
6. 当前生效 Provider 不允许直接删除，必须先切换到其他 Provider。
7. 退出应用、备份数据库和导出配置时，不得把密钥链中的凭据复制为 JSON、YAML 或其他明文文件。

原始工具配置可能已经包含凭据。此类文件的备份必须加密，不能以原文复制到 `backups/`；加密与恢复细节须在实现备份功能前按第 10 节明确。工具原生格式要求的运行时认证字段仅写入工具规定路径，不能额外生成 Agent Dock 自有认证文件。

### 5.5 云同步边界

WebDAV 和 S3 同步以应用生成的一致性配置快照为单位，不直接上传正在写入的 SQLite 主文件、WAL 文件或设备运行状态。密钥链凭据和设备专属目录不参与跨设备同步，资源实体文件按需同步；项目快照的同步范围见第 10 节。

云盘场景用于传递已关闭应用的便携目录，不支持多台设备同时打开同一数据库。该能力不提供自定义数据目录设置。

WebDAV、S3 的快照格式版本、资源清单、完整性校验、重复导入、删除传播、中断恢复及双端修改冲突须按 D06、D12 明确；未确定时不默认覆盖或合并。云盘整目录场景另外核对路径、凭据引用及加密备份的本机可恢复性，不将目录可复制等同于跨设备可直接恢复。

### 5.6 导入、导出、备份与恢复契约

Provider、MCP、Prompt、全量配置及云同步快照分别声明格式和版本、必填字段、非敏感资源范围、凭据引用表示及设备路径关联规则。导入先校验并展示受影响对象，再按已确认策略发布；重复 ID、同名不同对象、部分失败及跨版本不兼容的结果由 D12 明确，不能默认覆盖。深度链接另行明确 scheme、动作、载荷编码、大小限制和确认流程，不直接执行载荷中的命令。

备份策略须列明对象、自动触发条件、保留数量或期限、空间限制、清理条件和失败提示；使用中的恢复点不得被清理。恢复契约区分数据库、工具配置和资源文件，说明恢复前备份、密钥不可用、备份损坏及部分恢复的结果。含凭据恢复点按 D07 落实加密和实际恢复验证后才能用于覆盖操作；其他策略由 D12 明确。

### 5.7 用量指标口径

- 逻辑请求次数只统计最终尝试；尝试次数、已知 Token 和费用覆盖所有上游尝试，避免隐藏重试消耗。
- 失败率的分母只使用成功状态已知的终态逻辑请求；成功状态未知的记录单列，不归入失败。请求总耗时包含重试和等待，不能用最后一次尝试耗时代替。
- 首字节耗时以毫秒表示；输出速率以 Token/s 表示，其有效输出区间、有效样本及缺失用量处理按 D15 明确。缓存命中率须明确分子、分母及各协议的缓存 Token 归一化规则，不将未知用量当作零。
- 数据时间点和日汇总按 UTC 存储；界面时间区间、年度热力图的时区及日边界由 D15 明确。已知费用、未计价数量和来源匹配限制分别展示，历史费用不随现价自动改写。

### 5.8 CLI 与 WSL 边界

每个可管理 CLI 登记支持系统、安装渠道、版本识别依据、升级命令执行环境、权限要求和失败结果。批量升级逐工具报告结果；重复安装说明检测到的路径及来源，不自动删除未确认的安装。渠道选择、权限提升和升级失败后的恢复能力按 D13 明确。

WSL 登记发行版、Linux 工具路径和配置路径，明确读写在 Windows 还是 WSL 内执行、路径转换与权限规则。仅能访问目录不能证明能够在正确环境运行工具；支持范围和错误场景按 D13 验收。

## 8. 技术选型

### 8.1 选型结论

版本原则：桌面框架使用 Tauri 2，前端框架使用 React 19，样式框架使用 Tailwind CSS 4。其他依赖采用与项目兼容的稳定版本，准确版本以 `package-lock.json`、`src-tauri/Cargo.lock` 及工具链版本配置为准，不将“最新版本”作为每次开发或构建时的动态要求。不直接使用 Alpha、Beta、RC 或 nightly 版本；依赖升级仅针对安全、兼容性或明确功能需求进行。

| 层次 | 技术选型 | 选型说明 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | 使用系统 WebView，支持 Windows、macOS、Linux。 |
| 后端语言 | Rust 稳定工具链 | 负责文件、数据库、路由、进程和系统能力。 |
| 前端框架 | React 19 + TypeScript | 实现页面、业务组件和数据面板。 |
| 前端构建 | Vite | 管理开发服务与前端构建。 |
| UI 样式 | Tailwind CSS 4 + shadcn/ui | 使用工具类、主题令牌和组件变体组合样式，不新增语义化 CSS 类。 |
| 前端路由 | React Router | 管理工具、Provider、路由、会话和设置等页面。 |
| 前端状态 | Zustand | 管理需要跨组件共享的工具、Provider、主题和页面状态。 |
| 后端异步运行时 | Tokio | 承载本地路由、异步 I/O、进程调用和并发任务。 |
| Tauri 通信 | `invoke` + Tauri Events | `invoke` 处理请求响应，Events 推送路由状态、安装进度和任务日志。 |
| HTTP 服务 | Axum | 实现本地路由入口与流式响应。 |
| HTTP 客户端 | Reqwest | 访问上游 Provider 和 WebDAV 等 HTTP 服务，支持流式响应。 |
| 数据库 | SQLite | 使用嵌入式数据库，无需独立数据库服务。 |
| 数据库访问 | `rusqlite` + SQL 迁移文件 | 使用显式 SQL 与版本化迁移管理数据库。 |
| 配置解析 | `serde_json`、`toml_edit`、`serde_yaml` | 分别处理 JSON、TOML、YAML；TOML 保留注释和格式。 |
| Markdown 处理 | 原文存储 + `pulldown-cmark` 解析 | Prompt 和会话内容以原文为准，展示时再解析。 |
| 敏感信息存储 | `keyring` | 使用 Windows Credential Manager、macOS Keychain、Linux Secret Service 保存 API Key 和 OAuth 凭据。 |
| 日志 | `tracing`、`tracing-subscriber`、`tracing-appender` | 支持分级日志、滚动文件和结构化字段，敏感字段统一脱敏。 |
| 文件写入 | 临时文件 + `fsync` + 原子替换 | 防止应用异常退出导致工具配置文件损坏。 |
| 云同步 | Reqwest 实现 WebDAV，AWS SDK for Rust 实现 S3 | 同步一致性配置快照与允许同步的资源，遵循第 5.5 节的数据边界。 |
| CLI 管理 | Rust `Command` + `semver` | 调用系统包管理器或 CLI 安装命令，并比较工具版本。 |
| 打包发布 | Tauri CLI | 输出桌面可执行程序和便携发布包，具体平台产物与签名要求见第 10 节。 |

### 8.2 分层结构

```text
agent-dock/
├── src/                         # React 页面、组件和状态
└── src-tauri/
    ├── migrations/              # SQLite 数据库迁移
    └── src/
        ├── commands/            # Tauri 命令入口
        ├── application/         # 应用服务与业务流程
        ├── domain/              # Provider、MCP、Skills、项目等领域模型
        ├── repository/          # SQLite 数据访问
        ├── config/              # 各工具配置读写和字段映射
        ├── router/              # 本地路由、协议转换和故障转移
        ├── platform/            # 文件、进程、密钥链和系统适配
        └── main.rs              # Tauri 启动入口
```

业务依赖方向固定为：

```text
页面组件 → 类型化 API → Tauri Command → Application Service
                                              ↓
                                 Domain / Repository / Platform
```

Provider、MCP、Skills 和项目业务逻辑放在 Application Service 与 Domain 层；文件路径、文件写入、操作系统密钥链和进程调用由 Platform 层封装。HTTP 请求由路由、同步等对应后端模块处理，SQLite 由 Repository 管理。前端通过 `src/api.ts` 调用 Tauri 命令；Zustand 按需管理共享状态，不是每次请求的必经层。此目录树为目标模块划分，不表示当前目录均已实现。

### 8.3 配置文件处理策略

1. 每种 AI 工具单独定义配置路径、字段映射和写入规则。
2. Provider 切换只生成字段补丁，不整体覆盖配置文件。
3. 写入前读取并校验原文件，写入临时文件后再原子替换。
4. 首次改写前在 `config/backups/live-first-write/` 保存原始恢复点；含凭据的原文件按第 5.4 节加密，禁止直接明文复制。
5. 发布前失败时目标文件保持不变；已登记临时文件由待完成操作管理，部分发布和数据库提交失败按第 5.4 节及技术实现方案第 9 章恢复。
6. 写入前及原子替换前使用文件内容哈希检查外部修改。内容变化时重新合并，最多重算三次；无法安全合并或解析失败时停止写入并提示重新加载，不仅依据文件修改时间判断。

### 8.4 本地路由技术方案

- Axum 作为应用内部模块监听本地回环地址，默认端口由设置项管理；不单独部署路由服务。
- 使用统一的 `ProtocolAdapter` 接口处理不同上游协议。
- 请求入口先识别工具协议，再转换为统一的内部请求模型。
- 非流式响应与流式事件分别按已确认的协议契约转换，保留受支持语义、错误及取消行为；兼容边界和拒绝条件按 D04 明确。
- 每次请求记录 Provider、请求模型、实际模型、状态码、耗时和失败原因。
- 故障转移由队列、健康状态和熔断器共同决定。
- API Key 通过密钥链读取后只在请求内存中使用，不写入路由日志。

### 8.5 运行与发布方式

1. 用户直接启动 `agent-dock.exe`（或对应平台的可执行文件）即可使用。
2. 不安装 Windows Service、macOS LaunchDaemon、Linux systemd 服务或其他常驻系统服务。
3. 不部署独立后端、远程 API 服务、Docker 容器或数据库服务。
4. 本地路由、数据库访问、配置读写和任务调度都运行在桌面程序内部。
5. 发布包采用“可执行文件 + 运行依赖 + `config` 目录”的便携目录结构，也可以压缩成 ZIP 分发。
6. 程序退出前先保存路由恢复意图并恢复工具直连配置，再停止内部路由和后台任务，不能留下独立常驻进程。异常中断通过待完成操作记录在下次启动恢复。

### 8.6 数据库技术方案

数据库目标结构以[技术实现方案](实现方案.md)第 5 章为准，领域职责如下：

| 领域 | 数据表 | 职责 |
| --- | --- | --- |
| 应用设置 | `settings` | 应用偏好、共享路由监听参数、非敏感同步配置及恢复意图 |
| Provider | `providers`、`provider_models`、`model_pricing`、`provider_credentials` | 公共连接配置、模型能力、默认价格与覆盖价、密钥链引用 |
| 工具绑定 | `tool_bindings`、`tool_provider_bindings`、`tool_snapshots` | 已发布模式、Provider 选择、工具差异、文件哈希及同步状态 |
| 路由 | `routing_configs`、`routing_members`、`routing_model_aliases`、`provider_health` | 工具策略、故障转移或聚合成员、别名和健康状态 |
| 写入恢复与备份 | `pending_operations`、`pending_operation_files`、`backup_records` | 待完成发布、目标状态及备份文件索引 |
| MCP | `mcp_servers`、`mcp_bindings` | 服务配置与工具启用关系 |
| Prompt | `prompts`、`prompt_bindings` | 正文、来源与目标文件绑定 |
| Skills | `skill_repos`、`skills`、`skill_bindings` | 来源仓库、安装元数据与目标同步状态 |
| 项目 | `projects`、`project_snapshots` | 项目目录与按工具组织的资源快照 |
| 会话 | `session_files`、`sessions`、`session_messages` | 扫描游标、会话索引与消息 |
| 用量 | `request_logs`、`usage_dedup`、`usage_daily_rollups` | 尝试明细、持久去重与历史日汇总 |

SQLite 是应用配置和业务数据的唯一主存储。工具配置文件是由数据库生成的运行时投影；原始配置备份、Skills 实体文件、日志和外部会话原始文件保留在 `config` 目录或工具目录中。密钥链凭据不进入数据库，只保存引用关系。

### 8.7 测试与质量要求

- Rust 单元测试：配置字段补丁、协议转换、故障转移和费用计算。
- Rust 集成测试：SQLite 迁移、配置备份、原子写入和路由健康检查。
- 前端单元测试：Provider 表单、切换确认、筛选和状态展示。
- 前端端到端测试：新增 Provider、切换配置、MCP 同步和会话搜索。
- 每次发布前检查敏感字段脱敏、数据库迁移和跨平台路径处理。

## 9. 验收与需求追踪

### 9.1 核心验收标准

本章是三份文档的唯一验收入口。核心验收用于检查整体闭环；第 9.2 节覆盖全部 78 项需求，不能以核心条目通过替代逐项验收。

1. 能发现并读取能力矩阵确认支持的工具配置文件，未知版本或能力明确提示。
2. 能新增、编辑、删除和切换 Provider，被引用和当前生效项遵守删除规则。
3. 切换不丢失插件、Hooks、MCP、权限和未知配置。
4. 首次改写前存在可恢复的原始恢复点；含凭据恢复点使用加密备份并验证恢复能力。
5. 发布前失败时目标文件保持不变；部分发布、提交失败或应用异常退出后，按待完成记录进入明确恢复状态，不报告虚假成功。
6. 路由按确认的请求归属和协议契约转发；可重试失败按队列处理，不可重试及结果未知按既定策略结束。
7. MCP、Prompt、Skills 按已确认工具能力同步，重复同步与禁用不破坏未受管内容。
8. 能查看会话、Token、已知费用、未计价状态及脱敏请求错误，重试和重复扫描不重复累计逻辑请求。
9. 导出不含凭据正文；异机导入按已确认规则重新关联本机凭据和路径。
10. 正常退出先恢复直连再停路由；恢复失败按已确认策略处理，异常中断可在下次启动恢复。
11. 应用退出不留下独立路由或其他自建常驻后台服务；正常退出排空数据库写入队列。
12. 在确认的平台发布形式与依赖条件下，解压后可直接启动，不需部署独立后端、数据库服务或系统服务。
