# Agent Dock 项目开发目标

> 文档状态：目标交付要求；实现与验证状态以逐项交付记录为准。

在项目根目录中，依据[需求规格说明书](需求开发.md)和[技术实现方案](实现方案.md)完成 Agent Dock 开发。本文是开发与交付要求，不代表功能已经完成。

开发前先读取并理解实现方案文档，遵循其中的架构分层、模块边界、数据设计、配置安全写入和路由实现要求，并将方案映射到项目现有目录和代码结构。

先盘点实际工程、依赖、数据库设计、前后端通信方式和已有功能。已有模块按现有结构补齐；尚未初始化的模块按技术实现方案建立，不假设目标目录或接口已经存在。不要只输出方案、页面骨架、模拟数据或占位接口，要实现真实可用的业务闭环。

## 1. 开发重点

### 1.1 基础配置管理

- 使用 Tauri 2、Rust、React 和 TypeScript 架构。
- 支持需求规格说明书第 3 章所列工具配置的发现、读取、编辑和写入，各工具按规定的配置模式适配。
- 完成 Provider 列表、新增、编辑、删除、详情、搜索、排序、导入、导出、预设和自定义 Provider。
- 支持 Anthropic Messages、OpenAI Chat Completions、OpenAI Responses、Gemini Native 协议。
- 支持 Provider 一键切换、模型配置、配置差异展示，并保留工具中的其他用户配置。
- 首次写入前保存原始恢复点；含凭据文件必须按备份加密规则处理。写入采用临时文件、`fsync` 和原子发布；发布前失败时目标文件保持不变，部分文件已发布或数据库提交失败时保留待完成记录和恢复依据，按技术实现方案第 9 章处理。
- 实现基础设置、固定目录查看与打开、备份策略及运行状态管理。

### 1.2 资源同步与项目配置

- 支持 MCP 配置导入、编辑、导出、按工具同步以及批量启用和禁用。
- 管理 `CLAUDE.md`、`AGENTS.md`、`GEMINI.md` 等 Prompt 文件，并支持按工具启用或禁用。
- 支持 Skills 搜索、安装、版本检查、批量更新和按工具同步。
- 支持保存和切换项目配置，包括 Provider、MCP、Skills 和 Prompt 快照。
- 编辑页面离开前提示未保存修改。

### 1.3 本地路由与模型聚合

- 在桌面程序内部使用 Axum 实现本地回环路由服务和可配置端口。
- 支持多协议请求转换、流式响应转发、取消请求和错误处理。
- 支持按工具启用或关闭路由、Provider 故障转移队列、健康检查、失败计数、熔断恢复和请求日志；请求归属与重试边界须先按技术实现方案第 11 章明确。
- 记录 Provider、请求模型、实际模型、状态码、耗时和失败原因，并对敏感信息脱敏。
- 支持 Claude Code 和 Codex 的模型聚合、默认 Provider、按模型路由和状态提示。
- 应用退出前保存路由恢复意图，先恢复工具直连配置，再停止内部路由；中断操作在下次启动时恢复。

### 1.4 会话管理与用量统计

- 解析 Claude Code、Codex、Gemini CLI 等工具的本地会话日志。
- 支持按项目、时间、标题、目录、消息和会话 ID 搜索。
- 展示文本、思考过程、工具调用、工具结果、图片和失败步骤。
- 支持会话大纲、会话内搜索、步骤折叠、Markdown 导出、复制、恢复命令和批量删除。
- 统计请求次数、输入 Token、输出 Token、缓存命中率、耗时、响应速度、失败率、费用和错误信息。
- 支持按 Provider、模型、工具和时间筛选，提供趋势统计、年度热力图、模型自定义价格及 models.dev 价格导入能力。
- 支持 Provider 余额、订阅额度和额度重置时间展示，并完成 Hermes `MEMORY.md` 和 `USER.md` 管理。

### 1.5 跨平台适配与云同步

- 支持 Windows、macOS、Linux。
- 支持 WebDAV、S3 兼容存储的一致性配置快照同步，以及已关闭应用的云盘便携目录场景；不直接同步活动 SQLite 数据库或密钥链凭据。
- 支持 CLI 工具版本检查、安装、升级、批量升级和重复安装检测。
- Windows 下支持配置 WSL 内的工具目录。
- 提供可直接启动的便携发布目录和打包配置。

## 2. 架构与数据约束

- 遵循“页面组件 → 类型化 API → Tauri 命令 → Application Service → Domain / Repository / Platform”的依赖方向；Zustand 按需管理共享状态。
- 文件、进程、密钥链和操作系统差异由 Platform 层封装；HTTP 请求由路由、同步等对应后端模块负责，SQLite 由 Repository 管理，前端不直接执行这些操作。
- SQLite 使用 `config/config.db` 作为唯一主存储，数据库迁移放在 `src-tauri/migrations/`，目标表结构以技术实现方案第 5 章为准。
- 数据目录固定为程序目录下的 `config`，不使用用户主目录、系统应用数据目录或隐藏回退目录。
- API Key 和 OAuth 凭据使用系统密钥链，数据库只保存凭据引用和账号标识。
- API Key、Token 和认证 Header 不写入日志、Agent Dock 自有明文配置、明文备份或导出文件。工具原生格式要求的认证字段只写入工具规定路径，含凭据原文件的恢复点必须加密保存。
- 配置修改按规范化目标路径串行发布，并在原子发布前重新核对内容哈希；检测到外部变更且可安全合并时最多重算三次，无法安全合并时停止写入并提示重新加载。哈希核对不能消除不参与锁协作的外部写入竞态，跨进程协调与冲突边界按技术实现方案第 9、20.2 节明确。
- 删除 Provider 前检查引用；当前生效 Provider 必须先切换后才能删除。
- 删除操作需要二次确认，配置写入显示成功或失败；长耗时任务显示进度，可安全取消的任务提供取消入口，原子提交阶段不强行中断。
- 界面参考 cc-switch 的桌面布局和信息密度，使用 Tailwind CSS、shadcn/ui 和统一主题令牌，不新增语义化 CSS 类。
